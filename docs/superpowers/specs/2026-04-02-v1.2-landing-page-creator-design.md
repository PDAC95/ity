# v1.2 Landing Page del Creador — Design Spec

**Date:** 2026-04-02
**Milestone:** v1.2
**Status:** Approved

## Overview

Paula (creadora) puede solicitar la landing page de su escuela a traves de un flujo guiado con IA dentro de su dashboard. El resultado es un PRD estructurado (JSON) que el equipo de 12ity usa para personalizar el template elegido. La automatizacion de la ejecucion del PRD queda para un milestone futuro.

### User Story

> Como creadora, quiero poder elegir un template para mi escuela, conversar con un asistente que entienda lo que necesito, y saber que mi pagina web esta siendo creada — sin tener que saber de diseno ni programacion.

## Architecture

### New Database Tables

#### `landing_templates`

Catalogo de templates disponibles. En v1.2 se alimenta manualmente con URLs proporcionadas.

| Column | Type | Description |
|--------|------|-------------|
| id | uuid | PK |
| name | varchar(100) | Nombre del template ("Minimalista", "Yoga Flow") |
| slug | varchar(100) | URL-safe identifier, unique |
| category | enum | 'multipurpose' \| 'yoga' \| 'cooking' \| 'music' \| 'languages' \| 'business' |
| description | text | Descripcion corta del template |
| thumbnailUrl | text | URL de la imagen thumbnail para la galeria |
| previewUrl | text | URL externa del template completo (proporcionada manualmente) |
| sections | jsonb | Secciones disponibles del template (hero, about, services, testimonials, pricing, faq, contact) |
| isActive | boolean | Template visible en galeria (default true) |
| createdAt | timestamp | |
| updatedAt | timestamp | |

#### `landing_requests`

Solicitudes de landing page generadas por el chat guiado. El PRD vive aqui.

| Column | Type | Description |
|--------|------|-------------|
| id | uuid | PK |
| schoolId | uuid | FK -> schools.id |
| templateId | uuid | FK -> landing_templates.id |
| status | enum | 'chatting' \| 'pending_confirmation' \| 'confirmed' \| 'in_progress' \| 'ready' \| 'revision_requested' \| 'approved' |
| prdData | jsonb | PRD estructurado generado por el LLM (null hasta confirmacion) |
| chatHistory | jsonb | Historial completo de mensajes del chat |
| createdAt | timestamp | |
| updatedAt | timestamp | |

**Status flow:**
```
chatting -> pending_confirmation -> confirmed -> in_progress -> ready -> approved
                                                                   \-> revision_requested -> in_progress
```

Note: `revision_requested` y `approved` son estados futuros (requieren admin panel + flujo de revision). En v1.2 el estado final visible para Paula es `confirmed` ("Estamos trabajando en tu pagina").

#### `notifications`

Sistema de notificaciones in-app.

| Column | Type | Description |
|--------|------|-------------|
| id | uuid | PK |
| userId | uuid | FK -> creators.id (expandible a students en futuro) |
| type | varchar(50) | 'landing_ready' \| futuras categorias |
| title | varchar(200) | Titulo de la notificacion |
| message | text | Cuerpo del mensaje |
| isRead | boolean | Default false |
| metadata | jsonb | Datos extra (landingRequestId, URLs, etc.) |
| createdAt | timestamp | |

### New tRPC Routers

#### `landingTemplates` router

| Procedure | Type | Description |
|-----------|------|-------------|
| list | query | Lista templates activos, filtrable por categoria |
| getById | query | Detalle de un template con sus secciones |

#### `landingRequests` router

| Procedure | Type | Description |
|-----------|------|-------------|
| getBySchool | query | Obtiene la solicitud activa de la escuela (si existe) |
| create | mutation | Crea una nueva solicitud (status: chatting) |
| sendMessage | mutation | Envia mensaje al chat, guarda en historial. Respuesta del LLM via SSE endpoint separado (/api/chat/stream) |
| confirm | mutation | Paula confirma el resumen, status -> confirmed, genera PRD |

#### `notifications` router

| Procedure | Type | Description |
|-----------|------|-------------|
| list | query | Lista notificaciones del usuario, mas recientes primero |
| markAsRead | mutation | Marca una notificacion como leida |
| unreadCount | query | Numero de notificaciones sin leer (para badge en bell icon) |

### New Pages / Components

#### Dashboard Sidebar Update

- Replace "Coming Soon" placeholder for web page section with active "Mi Pagina Web" link
- Route: `/dashboard/landing`

#### `/dashboard/landing` — Template Gallery

- Grid de template cards (thumbnail, nombre, categoria badge, descripcion)
- Filtros por categoria (chips/tabs)
- Click en card -> modal/overlay con preview del template
- Preview con toggle mobile (375px iframe) / desktop (1280px iframe) cargando previewUrl
- Boton "Elegir este template" -> navega al chat
- Si ya tiene una solicitud activa, muestra el estado en lugar de la galeria

#### `/dashboard/landing/chat` — Chat Guiado

- Interface de chat (mensajes del asistente a la izquierda, Paula a la derecha)
- Input de texto con boton enviar
- Soporte para subir imagenes (reutilizar ImageUploadWidget de v1.1)
- Streaming de respuestas del LLM en tiempo real
- Al terminar la conversacion, el LLM presenta un resumen estructurado
- Boton "Confirmar" y "Quiero cambiar algo" sobre el resumen

#### Estado "En Proceso"

- Cuando `landing_requests.status >= confirmed`, la seccion "Mi Pagina Web" muestra:
  - Template elegido (thumbnail + nombre)
  - Estado actual: "Estamos trabajando en tu pagina web"
  - Mensaje: "Te notificaremos por correo y en la plataforma cuando este lista. Puedes cerrar esta ventana."
  - Opcion de "Ver resumen" para revisar lo que pidio

#### Notifications Bell (Header)

- Bell icon en el header del dashboard (junto al avatar)
- Badge con numero de notificaciones sin leer
- Dropdown con lista de notificaciones recientes
- Click en notificacion -> marca como leida + navega al recurso

### LLM Integration (Chat Engine)

**Provider:** Claude API (Anthropic)

**System Prompt Structure:**
```
Eres un asistente de 12ity que ayuda a creadores a definir su pagina web.

CONTEXTO DE LA ESCUELA:
- Nombre: {school.name}
- Descripcion: {school.description}
- Logo: {school.logoUrl}
- Colores: {school.branding.primaryColor}, {school.branding.accentColor}
- Creador: {creator.name}, {creator.bio}

TEMPLATE ELEGIDO: {template.name}
SECCIONES DISPONIBLES: {template.sections}

OBJETIVO: Recopilar toda la informacion necesaria para personalizar la landing page.
Necesitas saber:
1. Que ensena y a quien (si no esta claro en la descripcion)
2. Que secciones quiere activar del template
3. Para cada seccion: textos, imagenes, datos especificos
4. Si tiene fotos propias o necesita stock
5. Cualquier preferencia visual adicional

USA los datos que ya existen (nombre, bio, colores) como punto de partida.
NO preguntes lo que ya sabes.
Se conversacional, no hagas todas las preguntas de golpe.
Al terminar, presenta un RESUMEN estructurado por seccion.
```

**PRD Output Schema (JSON):**
```json
{
  "templateId": "uuid",
  "schoolId": "uuid",
  "generatedAt": "ISO 8601",
  "schoolContext": {
    "name": "Yoga con Paula",
    "tagline": "Transforma tu cuerpo y mente",
    "description": "...",
    "targetAudience": "Mujeres 25-45 interesadas en bienestar",
    "colors": { "primary": "#...", "accent": "#..." },
    "logoUrl": "https://...",
    "useStockPhotos": true
  },
  "sections": [
    {
      "type": "hero",
      "enabled": true,
      "content": {
        "headline": "...",
        "subheadline": "...",
        "ctaText": "...",
        "backgroundImage": "url or 'stock:yoga-studio'"
      }
    },
    {
      "type": "services",
      "enabled": true,
      "content": {
        "title": "Mis Clases",
        "items": [
          { "name": "Yoga Vinyasa", "description": "...", "price": "$500/mes", "image": "..." }
        ]
      }
    }
  ],
  "specialInstructions": "Notas adicionales de Paula"
}
```

**Streaming:** Dedicated Next.js API route (`/api/chat/stream`) using Server-Sent Events (SSE). The tRPC `sendMessage` mutation saves the user message and triggers the stream. The frontend connects to the SSE endpoint for the LLM response, then the completed assistant message is saved to `chatHistory` via a tRPC mutation.

**Cost consideration:** Each chat session ~2-5k tokens input, ~1-3k output. At Sonnet pricing, ~$0.01-0.03 per conversation. Acceptable for v1.2 scale.

### Email Notification

When `landing_requests.status` changes to `ready` (triggered manually by 12ity team for now):
- Send email to creator via Supabase email or a simple trigger
- Create in-app notification record
- Email content: "Tu pagina web esta lista. Entra a tu dashboard para verla."

## Data Flow

```
Paula in Dashboard
    |
    v
Template Gallery (browse, filter, preview mobile/desktop)
    |
    v
Select Template -> Create landing_request (status: chatting)
    |
    v
Chat Screen (LLM conversation with streaming)
    |
    v
LLM generates summary -> Paula reviews
    |
    v
Paula confirms -> Generate PRD JSON, status: confirmed
    |
    v
Dashboard shows "En proceso" state
    |
    v
[12ity team processes PRD manually]
    |
    v
Team sets status: ready -> notification + email to Paula
```

## Error Handling

- **LLM fails mid-conversation:** Show friendly error, allow retry. Chat history is saved, so no data lost.
- **Image upload fails:** Reuse v1.1 error handling from ImageUploadWidget.
- **Paula closes browser mid-chat:** Chat history persists in DB. When she returns, the conversation continues where she left off.
- **Template URL is broken:** Show placeholder image in gallery. Preview shows error message with "Template no disponible" text.
- **Duplicate request:** If Paula already has a `confirmed` or `in_progress` request, don't allow creating a new one. Show current status instead.

## Testing Strategy

- **Template gallery:** Renders correctly, filters work, preview loads in mobile/desktop modes
- **Chat flow:** Messages send/receive, streaming works, history persists across sessions
- **PRD generation:** Valid JSON output, all required fields present, matches template sections
- **Status transitions:** Correct states, UI updates accordingly
- **Notifications:** Created on status change, bell badge updates, mark as read works
- **Edge cases:** Empty gallery, LLM timeout, concurrent sessions

## Future Context (NOT in v1.2)

Documented here so future milestones can build on this foundation:

- **Automatic PRD execution:** An AI agent processes the PRD and applies changes to the template automatically. The PRD JSON schema is designed to support this.
- **Landing review flow:** Paula sees the finished landing, approves or requests changes. Requires admin dashboard for the 12ity team.
- **Domain selection:** After approval, Paula selects a custom domain or buys one through 12ity. Cloudflare Worker already exists for custom domain routing.
- **Admin panel:** 12ity team manages templates (add/remove/edit), processes landing requests, tracks status. Templates will be added from admin with preview URL.
- **Subscription/payments:** Paula pays for her 12ity subscription (Stripe). Required before the school goes public.
- **Student side (Cecilia):** Registration on school landing, student dashboard, course enrollment. Schema tables already exist (students, enrollments).
- **Courses & lessons:** Paula creates course structure, content, pricing. Schema tables exist (courses, modules, lessons).
