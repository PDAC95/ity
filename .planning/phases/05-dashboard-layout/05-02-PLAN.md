**Full rewrite of page.tsx** — replace existing stats/quick-actions with onboarding checklist.

1. This is an RSC page (no 'use client'). Fetch data server-side.
2. **Data fetching:**
   ```typescript
   const supabase = await createClient();
   const { data: { user } } = await supabase.auth.getUser();
   // user is guaranteed to exist — layout.tsx redirects if not
   
   const [{ data: creator }, { data: school }] = await Promise.all([
     supabase.from('creators').select('id, name, avatar_url').eq('id', user!.id).single(),
     supabase.from('schools').select('id, name, branding').eq('creator_id', user!.id)
       .order('created_at', { ascending: true }).limit(1).maybeSingle(),
   ]);
   ```
3. **Note on duplicate fetch:** Yes, the layout also fetches creator + school. This is acceptable in Next.js App Router because Supabase client uses fetch which is deduplicated by Next.js request memoization within the same render. The alternative (React context or searchParams passing) adds unnecessary complexity for data that is cheap to query.
4. **Derive checklist booleans:**
   ```typescript
   const hasSchool = !!school?.name;
   const hasSchoolLogo = !!(school?.branding as any)?.logo;
   const hasAvatar = !!creator?.avatar_url;
   ```
5. **Render:**
   ```tsx
   <div className="mx-auto max-w-2xl py-8 md:py-12">
     <OnboardingChecklist
       hasSchool={hasSchool}
       hasSchoolLogo={hasSchoolLogo}
       hasAvatar={hasAvatar}
     />
   </div>
   ```
6. The page content is centered with `max-w-2xl mx-auto` for a clean, focused onboarding experience.
7. When the checklist returns null (all complete + celebration finished), the page shows a clean empty state. For now, this is just the empty centered div — future phases will add dashboard content here.
8. Use dark text colors: any text outside the checklist card should use zinc-100/zinc-400 tones.
