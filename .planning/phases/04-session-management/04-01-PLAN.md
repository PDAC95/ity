Modify the existing `middleware.ts` to detect expired sessions when redirecting unauthenticated users from protected routes.

IMPORTANT: SESS-01 (silent token refresh) is already handled by `updateSession()` calling `supabase.auth.getUser()` which internally refreshes expired access tokens when the refresh token is valid. NO changes needed to `lib/supabase/middleware.ts` — it already works correctly.

In the `!user && isDashboard` block of `middleware.ts`, BEFORE the redirect:

1. Check if the request has a stale Supabase auth cookie: 
   ```typescript
   const hasSupabaseCookie = request.cookies.getAll().some(
     (c) => c.name.startsWith('sb-') && c.name.includes('-auth-token')
   );
   ```
   This uses `.includes('-auth-token')` (not `.endsWith()`) to catch both base cookies (`sb-<ref>-auth-token`) and chunked cookies (`sb-<ref>-auth-token.0`, `.1`, etc.) per Pitfall 3 in RESEARCH.md.

2. If `hasSupabaseCookie` is true, add `reason=session_expired` to the login URL:
   ```typescript
   if (hasSupabaseCookie) {
     loginUrl.searchParams.set('reason', 'session_expired');
   }
   ```

3. The `next` param is already being set (`loginUrl.searchParams.set('next', pathname)`) — keep it. The final URL will be `/login?next=/dashboard/whatever&reason=session_expired` for expired sessions, or `/login?next=/dashboard/whatever` for never-authenticated users.

Do NOT change:
- The callback rate-limit block (unchanged)
- The `authPages` redirect logic (unchanged)
- The matcher config (unchanged)
- `lib/supabase/middleware.ts` (SESS-01 is already working there)
