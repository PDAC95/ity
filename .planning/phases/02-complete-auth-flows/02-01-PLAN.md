  <action>
    1. Add '/reset-password' to the ALLOWED_PREFIXES array in `lib/auth/redirect.ts` — the password recovery flow needs to redirect there after OTP verification.

    2. Create `app/auth/confirm/route.ts` (NOTE: this is NOT inside the (auth) route group — it is at `app/auth/confirm/` as a top-level route so it maps to `/auth/confirm`):

    ```typescript
    // app/auth/confirm/route.ts
    import { type EmailOtpType } from '@supabase/supabase-js';
    import { type NextRequest, NextResponse } from 'next/server';
    import { createClient } from '@/lib/supabase/server';
    import { isAllowedRedirect } from '@/lib/auth/redirect';
    import { logAuthEvent } from '@/lib/auth/logger';
    ```

    The route exports a single GET handler that:
    a. Reads `token_hash`, `type`, and `next` from searchParams
    b. Validates redirect via `isAllowedRedirect(next)`
    c. If missing token_hash or type, redirects to `/login?error=auth_callback_error`
    d. Calls `supabase.auth.verifyOtp({ type, token_hash })` to verify the email OTP
    e. On error: logs auth_failure event and redirects to `/login?error=auth_callback_error`
    f. On success with type === 'email': provisions creator via idempotent upsert (same pattern as existing callback/route.ts — upsert into 'creators' table with fields: id, email, name (from user_metadata.full_name or email prefix), email_verified: true, using onConflict: 'id', ignoreDuplicates: true). Log upsert errors via logAuthEvent.
    g. On success with type === 'recovery': no creator provisioning needed, just redirect
    h. Redirects to `${origin}${safeNext}`

    Follow the exact code example from 02-RESEARCH.md Pattern 1. Use `await createClient()` (async).

    IMPORTANT: Do NOT use `exchangeCodeForSession` — that is for OAuth PKCE only. Email flows use `verifyOtp`.
